Point it at a folder. Every project inside gets its own window colour, written straight into .vscode/settings.json.

npx hue-shift-cli --random

Package is hue-shift-cli; the command it installs is hue-shift.

Commands

Colour one project

cd ~/code/my-app
npx hue-shift-cli --random

Colour everything under a folder, reproducibly

npx hue-shift-cli --root ~/projects --random --seed 42

Preview without writing

npx hue-shift-cli --root ~/projects --random --dry

Specific colour, title bar only

npx hue-shift-cli . --color amber --parts title

Colour plus a full theme

npx hue-shift-cli . --color teal --theme "Default Dark Modern" --icons Seti

Catch a project whose colours drifted

npx hue-shift-cli --root ~/projects --check

Your settings.json is safe

  • Merged, not replaced. Colour keys hue-shift does not own are preserved.
  • Comments survive. JSONC // and /* */ outside the colour block are untouched.
  • BOM and CRLF survive. Windows line endings stay Windows line endings.
  • Peacock stays in sync. If peacock.color exists, it is updated to match.
  • --reset is exact. It removes only the keys hue-shift wrote.

What it can't do

A CLI is not an extension. These need the VS Code API at runtime:

  • a status-bar colour chip
  • Live Share host & guest colours
  • “surprise me on startup”
  • command palette entries

Run Peacock alongside if you want them. Both write the same keys, so they don't fight.
