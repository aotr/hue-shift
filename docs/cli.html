Which projects get coloured

There are three ways to say what to colour. They can be combined.

No argument — the current directory

cd ~/code/my-app
npx hue-shift-cli --random

One project. The folder you are standing in.

--root <dir> — every folder inside

npx hue-shift-cli --root ~/Documents/projects --random --seed 42

Every immediate subfolder becomes a project. Hidden folders (.git, .config) and node_modules are skipped. Results are sorted by name, so the same seed always maps to the same project. Scanning is one level deep — nested packages need their own run or an explicit path.

Positional paths — name them exactly

npx hue-shift-cli ./api ./web ./admin --random

Each path is one project. Use this when the projects are not siblings.

Combining them

npx hue-shift-cli --root ~/code ~/scratch/experiment --random

Targets are de-duplicated by absolute path, so listing a folder twice colours it once. ~ is expanded. A path that is not a directory is a usage error.

Watch out: --color with --root paints every project the same colour. To give each one a different colour, use --random.

Choosing a colour

Random, but never muddy

npx hue-shift-cli --root ~/projects --random --seed 42

Hues are placed on a jittered even grid, at least 22° apart, with saturation 55–78% and lightness 25–38%. That band keeps white or black text readable on the bar. The wheel holds 16 hues at that spacing; past 16 projects the gap shrinks and the tool takes the widest empty arc.

--seed <n> makes the sequence reproducible. Same seed, same folders, same colours — on any machine.

One exact colour

npx hue-shift-cli . --color "#6d28d9"
npx hue-shift-cli . --color 6d28d9
npx hue-shift-cli . --color "#0af"
npx hue-shift-cli . --color teal
InputAccepted
#rrggbbSix digits, with or without #, any case
#rgbShorthand, expanded
#rrggbbaaAlpha is dropped — VS Code bars are opaque
nameOne of the 20 built-in names, case-insensitive

Anything else is a usage error, and nothing is written.

Which colour wins

When several sources are present, the first match wins:

  1. --color on the command line
  2. color in the project's .hue-shift.json
  3. color in ~/.hue-shift.json
  4. --random, or random: true in a config file
  5. A stable colour derived from the project's position in the sorted list

--seed only affects the random step. Without --random it does nothing.

Which parts of the window

npx hue-shift-cli . --color teal --parts title,status

Default is title,activity,status. Each part owns a fixed set of keys:

PartKeys written
titletitleBar.activeBackground, titleBar.activeForeground, titleBar.inactiveBackground, titleBar.inactiveForeground
activityactivityBar.background, activityBar.foreground, activityBar.inactiveForeground, activityBar.activeBackground
statusstatusBar.background, statusBar.foreground, statusBar.debuggingBackground, statusBar.noFolderBackground
borderwindow.activeBorder, window.inactiveBorder
tabtab.activeBackground, tab.activeForeground, tab.activeBorderTop
sashsash.hoverBorder
sidebarsideBar.background, sideBar.foreground

Foreground colours are chosen automatically: whichever of black or white has the higher contrast on that background. Inactive variants use the same colour with alpha appended (cc, 99, 88).

An unknown part name is a usage error listing the valid ones.

Shifting parts apart

npx hue-shift-cli . --color teal --parts title,status \
  --adjust title=lighten,status=darken --adjust-pct 8

A flat colour across three bars looks like one big block. --adjust moves individual parts along the lightness axis so they read as related but distinct.

ModeEffect
lightenRaises lightness by --adjust-pct points
darkenLowers lightness by --adjust-pct points
noneLeaves the part at the base colour

--adjust-pct defaults to 6. Values are clamped, so a light colour cannot be lightened into white.

The reported colour stays the base colour; only the written keys shift. --check without --color therefore validates whatever is on disk — it has no base to compare against.

Leaving one key alone

npx hue-shift-cli . --color teal --exclude statusBar.noFolderBackground
npx hue-shift-cli . --color teal \
  --exclude statusBar.noFolderBackground \
  --exclude tab.activeForeground

Repeatable. Excluded keys are never written, and any value already there is preserved. Useful when a theme or another extension owns a particular bar.

Theme and icons

npx hue-shift-cli . --color teal \
  --theme "Default Dark Modern" --icons Seti

Sets workbench.colorTheme and workbench.iconTheme in the same file, so a project can carry its whole visual identity. Both are ordinary settings — --reset leaves them alone, because they are not colour keys.

Use the exact name VS Code shows in the theme picker. A wrong name is written as-is and VS Code falls back to its default.

Modes

Write — the default

npx hue-shift-cli . --color amber

Merges the colour block into .vscode/settings.json, creating the file if needed.

--dry — show the plan, write nothing

npx hue-shift-cli --root ~/projects --random --seed 42 --dry

Every line reports the colour it would use. The filesystem is untouched, including the .vscode directory.

--check — two different jobs

npx hue-shift-cli --root ~/projects --random --seed 42 --check
npx hue-shift-cli . --color amber --check

With a colour (from --color or a config file): compares every expected key against what is on disk and reports each difference.

Without a colour: validates what is there — that a colour exists, and that its foreground reaches 4.5:1 contrast.

Exits 2 on drift, invalid JSON, or a project with no colour. Safe in CI.

--reset — remove everything it wrote

npx hue-shift-cli --root ~/projects --reset
npx hue-shift-cli . --reset --dry

Removes every key hue-shift manages, drops the workbench.colorCustomizations object if it becomes empty, and deletes peacock.color only if it still holds a colour hue-shift wrote. Other settings, comments, BOM and line endings survive. Running it twice is safe — the second run reports clean.

--parts and --adjust are ignored by reset: it removes all managed keys, not just the selected parts.

--json — for scripts

npx hue-shift-cli --root ~/projects --check --json
{
  "version": "1.0.2",
  "mode": "check",
  "results": [
    {
      "project": "api",
      "dir": "/home/me/projects/api",
      "color": "#0f766e",
      "status": "ok",
      "diffs": [],
      "warnings": []
    }
  ]
}

Statuses: created, inserted, updated, unchanged, dry, ok, drift, missing, invalid, reset, clean.

Config files

Two files, merged. The project wins over the global one. CLI flags win over both.

~/.hue-shift.json — defaults everywhere

{
  "parts": ["title", "activity", "status"],
  "adjust": { "activity": "lighten" },
  "adjustPct": 6,
  "theme": "Default Dark Modern",
  "icons": "Seti"
}

<project>/.hue-shift.json — this project only

{
  "color": "teal",
  "parts": ["title"],
  "exclude": ["statusBar.background"]
}
KeyTypeMeaning
colorstringHex or named colour, pinned for this project
randombooleanUse a generated colour when no color is set
seednumberSeed for the generated colour
partsstring[]Which window parts to colour
adjustobject{ "title": "lighten" }
adjustPctnumberLightness shift, default 6
excludestring[]Colour keys to never write
themestringworkbench.colorTheme
iconsstringworkbench.iconTheme

A malformed config file stops the run with the file name and the JSON error.

Exit codes

CodeMeaning
0Success. Also --check when everything matches.
1Usage error: unknown flag, bad colour, bad part, missing directory.
2A project failed: drift, invalid JSON, unreadable file.
npx hue-shift-cli --root ~/projects --random --seed 42 --check || echo "palette drifted"

Recipes

Colour everything once, reproducibly

npx hue-shift-cli --root ~/Documents/projects --random --seed 42

Preview before touching 75 repos

npx hue-shift-cli --root ~/Documents/projects --random --seed 42 --dry

Give each project a pinned colour that survives a rescan

# in each project
echo '{ "color": "teal" }' > .hue-shift.json
npx hue-shift-cli .

Title bars only, no status bar noise

npx hue-shift-cli --root ~/code --random --parts title

Two-tone window

npx hue-shift-cli . --color "#6d28d9" --parts title,status \
  --adjust title=lighten,status=darken --adjust-pct 8

Monorepo: neutral root, coloured packages

npx hue-shift-cli . --color slate --parts title
npx hue-shift-cli packages/api packages/web packages/admin --random --seed 7

CI guard

npx hue-shift-cli --root . --random --seed 42 --check --json

Undo everything

npx hue-shift-cli --root ~/Documents/projects --reset

Machine-readable report of what changed

npx hue-shift-cli --root ~/code --random --json | jq -r '.results[] | "\(.project) \(.color)"'

All flags

FlagValueWhat it does
--rootdirTreat every subfolder of dir as a project. Repeatable.
--random—Generate a colour per project, spread across the wheel.
--seedintegerMake --random reproducible.
--colorhex or nameUse one exact colour.
--list-colors—Print the built-in palette and exit.
--partslistComma-separated parts. Default title,activity,status.
--adjustpart=modeComma-separated lighten, darken, none.
--adjust-pctnumberLightness shift, default 6.
--excludekeyNever write this colour key. Repeatable.
--themenameAlso set workbench.colorTheme.
--iconsnameAlso set workbench.iconTheme.
--check—Report drift or validate contrast. Writes nothing.
--reset—Remove every managed colour key.
--dry—Print the plan, write nothing.
--json—Machine-readable output.
-h, --help—Usage text.
-v, --version—Print the version.

--check and --reset cannot be combined.
